PrepFlow Security Specification & Data Integrity

Last Updated: July 11, 2026

At PrepFlow, we design our application with a **Zero-Trust, client-side first architecture**. As software engineers ourselves, we understand that you place high value on your study analytics, mistake logs, and especially the credentials (API keys) used for AI features.

This document details how we handle data security, browser sandboxing, cloud sync partition boundaries, and local device access.

1. Local Storage Sandboxing by Default

PrepFlow is designed to run entirely offline with zero mandatory server registrations.

  • IndexedDB & LocalStorage: All study topics, dynamic schedules, mistake journals, and STAR stories are written directly to your browser's private offline storage. No central database stores this info unless you explicitly choose to sync.
  • Browser Sandbox isolation: Since all computations execute on the client device, your data is isolated from other sites by standard browser Same-Origin Policy (SOP).

2. Zero-Risk API Key Architecture

To power mock interviews and interactive study assistance, PrepFlow lets you configure custom API keys for providers like **Google Gemini, Cerebras, and Groq**.

  • Direct Request Dispatching: When you run an AI mock interview, your browser dispatches HTTP requests directly to the AI provider endpoint (e.g. `https://generativelanguage.googleapis.com/`).
  • No Middleman Server: We do not operate a proxy server or gateway. Your API keys are **never** routed through, stored on, or logged by PrepFlow servers.
  • Encrypted in LocalStorage: Keys are kept purely in your browser's memory, ensuring you retain full ownership and revocation rights.

3. Fortress-Grade Cloud Sync Boundaries

If you choose to synchronize your progress across devices (e.g. desktop to mobile Capacitor shell), PrepFlow utilizes **Firebase Authentication and Firestore** under strict rules:

  • Authenticated User Isolation: Firestore rules enforce absolute partition mapping: allow read, write: if request.auth != null && resource.data.userId == request.auth.uid; This prevents any user from querying, writing, or viewing another user's records.
  • TLS 1.3 Transport Encryption: All cloud sync data is encrypted in transit using standard Transport Layer Security.
  • Immutable Identity Links: Document rules reject attempts to modify `userId` tags post-creation, eliminating spoofing risk.

4. Device Permission Privacy

Our interactive features require webcam and microphone access:

  • Microphone Permission (Mock Interviews): Your voice is captured locally to convert speech to text. The audio buffer is processed strictly inside the browser and is only sent to the configured transcription API using your key.
  • Webcam Permission (Gesture Controls): Camera streams are processed locally using **Google MediaPipe computer vision models** on your GPU/CPU thread. The frames are parsed for hand landmark coordinates and immediately discarded. Video streams are **never** recorded or uploaded to the cloud.
